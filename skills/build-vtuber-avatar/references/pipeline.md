# 入力からPSD・口差分を作る

## 入力を用意

新規プロジェクトは正面寄りのアニメ絵を想定する。目口が隠れる、大きく横を向く、髪と背景が融合する、手が顔を隠す画像では分解後に補完が必要になる。元絵は保持し、必要な派生は別名にする。

推奨入力は透過の8bit RGBA PNG。現在の検証例は1280px級だが、1280px座標や女性・特定衣装を必須にしない。画像生成や背景除去が必要なら対応する画像生成スキルを使う。完成画像がある場合はキャラを新しく描き直さない。

`scripts/create_project.py` が作る `run.json` に入力ハッシュと未検証状態が残る。アルファ付きヘッダーのチェックは透明画素や絵の品質を証明しない。画像を見て、透明画素と空でない描画を画素単位でも確認する。

## 実行先を選び、GPUで分解

既存の許可・GPU・依存ライブラリ・予算から実行先を選ぶ。Colabを必須にしない。生成が終われば同じPSD・ログ・ハッシュを次の工程へ渡す。固定版は次の通り。

| 対象 | ソース |
|---|---|
| See-through | https://github.com/shitagaki-lab/see-through / `a25a5498e031dc7fe01232d05dadaf67736277fb` |
| Anime2.5DRig | https://github.com/852wa/Anime2.5DRig / `7ddbd9943ea3152561b3dc8348fd752c850f3e95` |
| 既存の動作検証例 | https://github.com/naochan3/vtuber-dev / `52ff2115d7b7d95493b11aec8805cb8c49d27ec5` |

ColabノートブックはPython 3.12、Torch 2.8.0+cu128、BF16対応GPUの既存検証経路。L4で成功した経路だが、自宅や他GPUの所要時間として転記しない。実行前に公式README・LICENSEと使用重みのモデルカードを確認する。

Colabならテンプレートの `notebooks/seethrough-colab.ipynb` を使う。許可されたアカウントと既存契約で実行する。未ログインならユーザーがログインするまでGPU実行は待つ。会社側のアカウントを勝手に使わず、Drive全体のマウントやGitHubトークンは不要。ノートブックへの画像アップロードが許可された範囲か確認する。

ローカルや別GPUホストなら、公式READMEに従って専用Python 3.12環境・CUDA用PyTorch・requirements・assetsを準備する。環境の新規構築は許可された機器だけで行う。既存のGPU環境がある場合はそれを優先し、Windows・Linux・ドライバの互換性は実行時に確認する。ネイティブWindowsや全GPUでの動作を保証せず、必要な環境変更を無断で行わない。

準備済み環境では `scripts/generate-psd.py` に実行Python・固定版ソース・入力・新規出力を渡す。これはColab固有のAPI・Drive・ユーザー名に依存しない。入力の透過画素・固定コミット・上書き禁止を確認し、時間上限・失敗ログ・入力ハッシュを共通形式で記録する。

```text
python scripts/generate-psd.py --python <GPU環境のPython> --checkout <See-through固定版フォルダ> --image input/source.png --output <新規生成フォルダ>
```

この入口のプロセス制御は一時環境の模擬推論でも検査するが、実GPUによるローカル生成の実績とは区別する。既存PSDを渡された場合はGPU生成を省き、以降の名前・画素・動き・前後関係の同じ検査を行う。

推論CLIは `inference/scripts/inference_psd.py --srcp <PNG> --save_dir <出力> --save_to_psd --tblr_split --group_offload`。初回推論が長いため、ログを保持して進捗を確認する。テンプレートは1実行30分を上限にして停止する。契約や利用者の予算により短くできる。失敗原因を調べず新たなGPU実行を反復しない。

既存の前提が合わない場合は、会社PCの環境を変更して通さない。ログと途中成果物を保存し、必要な実行先・バージョンを明示する。

## PSDの名前と画素

See-throughの `eyebrow-l/r`, `eyewhite-l/r`, `irides-l/r`, `eyelash-l/r`, `ears-l/r`, `handwear-l/r` は、同梱の `normalize-psd.py` で番号付き形式へ変換する。既存の番号付きPSDには余計な変更をしない。

変換の前後で画像寸法・レイヤー数・合成画素の一致を確認する。レイヤー名だけの修正と、画像補完を分けて記録する。PSDには8bit RGB・アルファ・ビューア上限128MBを確認する。

## 口差分

元PSDに口の開閉差分があるなら活用する。片方しかなければ、元絵の口・画風を参照して透明な単体スプライトを生成する。

プロンプトの骨子:

> 参照キャラに一致する画風・線・色の、話している開き口だけを1個。口以外の顔・肌・鼻・目・文字は入れない。透明背景、余白あり。元キャラの口角・歯や牙の特徴を保ち、勝手な特徴を追加しない。

`add-speaking-mouth.py` は元PSDへ単体の開き口を追加し、元レイヤーの画素を照合する。根元の閉じ口サイズから初期寸法を求めるが、口の高さ・幅・位置は必ずプレビューで合わせる。必要なら `--width` / `--height` を指定する。以前の60×30pxは一例であり固定値にしない。

この補助はSee-throughの平坦なレイヤーを前提とする。グループ構造や重複名があるPSDにはそのまま適用せず、構造と元画素の保存方法を確認して対応する。見えない肌や服の補完が必要な場合も、この口追加だけで解決した扱いにしない。

Colabは初期PSD・口差分PSD・プレビュー・元画像・ログを素材ZIPとして返す。**リグ設定JSONはまだ入っていない**。GPUの一時ファイルは消えるため、取得してローカルの日時付き出力へ保存する。

## ビューアと設定

許可された開発環境では `setup-anime25d.ps1` で固定版へ共通差分を適用する。ソースSHA256と置換箇所を照合し、未知の版や別編集は上書きしない。元コードは保管する。

最終PSDを `avatars/avatar.psd` にコピーし、ビューアで読み込む。顔・首・肩・左右の目・眉・口・髪を割り当て確認し、そこから `avatar.rig.json` を書き出す。再生成・別PSDへ旧JSONを無理に当てない。未完成の設定を既存キャラから複製して完成に見せない。
