# 画像から動くVTuberを作る

画像を受け取り、許可されたGPU環境でPSDへ分け、同梱の改良版Anime2.5DRigで動かす。ユーザーに座標や内部IDの指定を求めず、画像の確認・差分制作・設定・検査をエージェント側で進める。**Colab・自宅GPU・他のGPUホストは実行先の違いとして扱い、成果物と品質基準は共通にする。**

## 目指す成果物

- 入力の画風・キャラ属性・衣装を保つPSDと、同じmodelIdの設定JSON。
- 頭の左右・上下・傾き、肩と胸の追従、呼吸演出、左右独立のウィンク、眉、口パク、毛束ごとの髪の揺れ。
- 必要な画像別の首・襟・背面布のマスク。元絵とPSDの画素は保持する。
- カメラなしの動作サンプル、検査記録、起動できるコード一式、OBS・別PC用の引継ぎ。

新しい絵で初版を作る経路と、既存PSDの修正経路を選ぶ。現在の方式の修正なら素材を再生成する前に原因を調べる。画像制作だけ・3D化・Live2D制作の依頼へ、この方式を勝手に押し付けない。

## 実行

1. **入力を見て実行先を決める。** 透過・正面寄り・目口と髪が見えるか確認する。目的や環境は会話から引き継ぎ、不足する認証・画像・実行許可だけを確認する。GPU利用や公開の許可はこのスキル自体から得た扱いにしない。
2. **新規フォルダへ一式を作る。** [scripts/create_project.py](scripts/create_project.py) は透過用PNGのヘッダーを確認し、[assets/template](assets/template/) と元画像をコピーする。アルファ付き形式だけでは透明背景の証明にならないので、画素も確認する。既存フォルダは上書きしない。
3. **PSDと必要な差分を作る。** 新しい絵では [references/pipeline.md](references/pipeline.md) に従う。既存PSDなら生成を省く。開き口等を描く必要があるときだけ、利用可能な画像生成機能・スキルを使い、参照画像の画風に合わせる。入力にない性別・体形・演出を足さない。
4. **共通の動きと画像別の前後関係を整える。** [references/motion-and-occlusion.md](references/motion-and-occlusion.md) を読む。共通差分はテンプレートのmanifestで適用し、襟・腕・衣装のマスクは対象PSDを見て作る。前のキャラのmodelId・金色判定・固定座標・JSONを流用しない。
5. **実際の動きを検査して直す。** [references/checks-and-handoff.md](references/checks-and-handoff.md) の回帰検査と目視比較を行う。テスト合格だけで完成にしない。左右上下と傾きの正負、ウィンク、目の再開眼、髪の停止後、首と襟、衣装と腕を確認し、崩れがあれば修正して該当検査を再実行する。
6. **配布する。** 最終PSDを `avatars/avatar.psd`、同じPSDから書き出した設定を `avatars/avatar.rig.json` に置く。画像別マスク・コード・証跡・引継ぎを含むZIPを保存し、ハッシュとCRCを検証する。カメラ・OBS・TikTokの実確認ができなければ、その項目を未確認として渡す。

作成例:

```text
python <このスキルのパス>/scripts/create_project.py --image <入力PNG> --output <新規作業フォルダ>
```

## 判断と限界

- 自動分解だけで、隠れた肌・髪・服の背面が正しく補完されるとは限らない。見える崩れを検査・修正する手順が品質の中心。
- 肩や胸は顔の動きから推定した演出。呼吸は自動周期で、本人の呼吸・体・肩を測っていない。
- 共通の係数は初期値。画像の比率・構図・毛束・衣装に合わせて調整する。根元の固定、頭と胴体の遅れ、独立した目、瞳の再開眼時の伸縮なしを維持する。
- 会社PC等で重い処理が許されない場合は、そこで環境を構築せず許可済みのColab等を使う。GPU処理を実行できない場合も、レビュー可能なノートブックと一式の準備までは進める。
- 新規課金、別モデル方式、OS・セキュリティ設定の変更、素材公開は依頼の許可範囲で扱う。モデル重みや認証情報を配布しない。
- 本スキルは既存一例を基にした再現手順。**任意の画像から無調整で同じ品質になることは未検証**。新しい画像の実績を得たら、証拠のある改善だけを狭く反映する。
